================================================================
RUGBY LEAGUE TAKEOVER - SPONSOR BANNER ARTWORK SPEC
For: Stadium Swim (and any future banner sponsor)
Slot: "Banner Top" - the full-width strip under the nav on every page
================================================================

SHORT VERSION - ASK THEM FOR TWO FILES
--------------------------------------
  1. DESKTOP    1456 x 180 px   (displays at 728 x 90)
  2. MOBILE      960 x 300 px   (fills the phone's full width)

  Format:  PNG (still) or GIF / WebP (animated) - all supported
  Colour:  RGB / sRGB
  Max size: 300 KB each still, 1 MB each animated

That is everything. Two files, those two pixel sizes.
MOVING BANNERS ARE SUPPORTED - see the ANIMATION section below.


WHY TWO FILES
-------------
The banner is responsive. On a computer it is a wide, short
leaderboard strip. On a phone that shape is unreadable, so the site
swaps to a shorter, chunkier mobile strip instead. The artwork has to
be designed for each shape - a desktop banner shrunk to phone width
becomes an unreadable sliver.

The site serves the right one automatically: you upload both and tag
one "Desktop" and one "Mobile" in the admin (see UPLOADING below).


FULL SPECS
----------

DESKTOP BANNER
  Display size .... 728 x 90 px   (IAB Leaderboard - industry standard)
  Supply at ....... 1456 x 180 px (2x, for retina/4K screens)
  Aspect ratio .... 8.09 : 1 (very wide and short)
  Shows on ........ screens 768 px wide and up (laptops, desktops,
                    iPad landscape)

MOBILE BANNER
  Display size .... edge to edge, about 360-430 px wide and
                    113-134 px tall depending on the phone
  Supply at ....... 960 x 300 px
  Aspect ratio .... 3.2 : 1  (THIS is the number that matters -
                    the banner stretches to the screen, so the
                    ratio is fixed but the width is not)
  Shows on ........ screens under 768 px wide (all phones,
                    iPad portrait)

  The mobile banner is FULL BLEED - it runs the whole width of the
  phone screen, edge to edge. 960 x 300 is supplied oversized on
  purpose so it stays sharp when stretched across the widest phones
  (about 2.2x on a 430 pt screen).

Supply at 2x and let the site scale down - that is what keeps it
sharp on a modern phone or a Retina MacBook. Do NOT supply at 1x
only; it will look soft.


FILE FORMAT - WHAT TO ASK FOR
-----------------------------

STILL BANNERS
  PNG  - USE THIS for anything with a logo, text, flat colour or
         sharp edges. Which is nearly every sponsor banner.
         PNG-24 with a white or solid background.

  JPG  - only if the banner is mostly a PHOTOGRAPH (e.g. a shot of
         the pool deck). Save at quality 80-85.

  File size: under 300 KB each.

ANIMATED / MOVING BANNERS - YES, THESE WORK
  GIF   - animated GIF plays fine. The familiar option, and the one
          most agencies will offer by default. Downside: it is
          limited to 256 colours and the files are big, so a
          photographic or gradient-heavy animation will look banded.

  WebP  - animated WebP also plays fine, and it is the BETTER ask:
          full colour, and roughly 3x smaller than the same GIF.
          If Stadium Swim's designer can export one, take it.
          Supported by every browser the site runs in, including
          the iOS and Android apps.

  Either is fine. If in doubt, ask for "animated GIF, or animated
  WebP if you can export it".

  File size for animation: under 1 MB desktop, under 500 KB mobile.
  This matters - the banner is at the top of every page, and a
  4 MB GIF is a visibly slower site for anyone on mobile data.

  NOT SUPPORTED - DO NOT ASK FOR:
    - MP4 / MOV / WebM or any video file. The banner is an image
      slot, not a video player. A video file will not display
      at all.
    - SVG      (animated or not - will not render reliably here)
    - PDF, AI, EPS, PSD, TIFF  (not web formats - if they only have
      these, ask them to export to the sizes above)

  TRANSPARENCY: avoid it, animated or still. The site background is
  dark, so a transparent PNG/GIF with dark text will disappear. Ask
  for a solid background baked in.

ARTWORK / DESIGN NOTES TO PASS ON
---------------------------------
  - SAFE MARGIN: keep logos and text at least 12 px (desktop) /
    8 px (mobile) in from every edge, measured at display size.
    So 24 px / 16 px in on the 2x files they supply.

  - The image is centred and scaled to fit the slot. It is never
    cropped and never stretched - so if they supply the wrong
    aspect ratio it will simply render smaller with empty space
    either side. Hence: exact ratios, please.

  - TEXT SIZE: minimum 14 px at display size (28 px on the 2x file).
    A desktop banner is only 90 px tall - a paragraph will not fit.
    One line of headline plus a logo plus a call to action is the
    realistic maximum.

  - No small print, no phone numbers in 8 pt type, no QR codes.
    Nobody can read them at 90 px tall.

  - It sits on a DARK background with a thin border. A banner with a
    dark edge will blend into the page - a light or brand-coloured
    background reads much better.

  - They should also supply:
      * the CLICK-THROUGH URL (where tapping the banner should go -
        must be https://)
      * the ALT TEXT / campaign name (shown to screen readers, and
        used as the ad's title in the admin)
      * the START and END dates if it is a fixed-term campaign


IF THEY SEND AN ANIMATED BANNER - RULES TO PASS ON
--------------------------------------------------
  - Keep it to about 5 seconds. Looping is fine.

  - NO RAPID FLASHING. Nothing that flashes or strobes more than
    three times per second. This is a genuine accessibility and
    seizure-safety rule (WCAG 2.3.1), not a style preference.

  - The FIRST FRAME must work on its own. It is what shows while
    the file is still loading, what shows if the file fails, and
    what appears in any screenshot of the site. It should contain
    the logo and the message - not a blank lead-in.

  - Gentle movement reads better than frantic movement at 90 px
    tall. A slow wipe, a fade between two messages, or a subtle
    shine is plenty. Anything faster looks like a pop-up ad.

  - Same pixel dimensions as the still versions: 1456 x 180
    desktop, 640 x 200 mobile.


UPLOADING (admin side - internal note)
--------------------------------------
Command Centre -> Ads -> one ad, two creatives:

  Title ............... the campaign name
  Ad Creative Desktop . the 1456 x 180 file
  Ad Creative Mobile .. the 960 x 300 file  (optional)
  Position ............ Banner Top
  Size ................ Leaderboard (728 x 90)
  Device Target ....... All Devices
  Target URL .......... where it clicks through to

That is it - ONE ad record. The site shows the desktop file on
screens 768 px and wider and the mobile file below that, and the
impression and click counts stay on the single record so the numbers
you report back to the sponsor are the real totals.

If you leave the mobile creative empty, the desktop file is used
everywhere. Nothing breaks and nothing is cropped - it just renders
smaller, with empty space either side, on a phone.

(Older setups used TWO ad records paired with Device Target =
Desktop / Mobile. That still works, but it splits the stats across
two rows and you have to keep the URL and dates in sync by hand.
One record with two creatives is the better way now.)

----------------------------------------
"Could we get the banner artwork as two files please - 1456 x 180 px
for desktop and 960 x 300 px for mobile (both oversized on purpose
so they stay sharp - the mobile one runs edge to edge on the phone
screen, so it gets stretched). PNG is ideal for a still
banner. If you'd rather it moved, an animated GIF works, or animated
WebP if you can export one - keep it to about 5 seconds, no rapid
flashing, and under 1 MB. Either way: solid background rather than

you can also send the link it should click through to, we'll get it
live. One thing we can't take is video files - MP4 won't display."
